# 用户使用文档

## 1. 文档目的

本文档面向接口调用方、测试同学和一线运维同学，介绍如何创建迁移任务、查询状态、执行控制，以及如何理解常见返回结果。

## 2. 使用前提

- 源路径必须存在，且必须是目录
- 目标路径不能与源路径互相嵌套
- 调用方需要能够访问本服务的 HTTP 地址
- 服务所在机器需要对源/目标目录有读写权限

## 3. 创建迁移计划

接口：

```text
POST /api/transfer
```

请求体：

```json
{
  "sourcePath": "C:/data/source",
  "targetPath": "D:/data/target",
  "verificationMode": "SIZE_AND_MTIME"
}
```

字段说明：

- `sourcePath`：源目录绝对路径
- `targetPath`：目标目录绝对路径
- `verificationMode`：校验模式，可选 `SIZE_AND_MTIME` 或 `FULL_HASH`

返回特征：

- HTTP 状态码为 `202 Accepted`
- 返回体中的任务状态为 `PLANNING`
- 表示任务已经创建成功，但目录扫描仍在后台进行

## 4. 轮询任务摘要

接口：

```text
GET /api/transfer/{taskId}
```

建议：

- 在状态为 `PLANNING` 时，每 1 到 3 秒轮询一次
- 只有当状态变为 `PLANNED` 后，才应发起执行

常见状态：

- `PLANNING`：后台正在扫描并切批
- `PLANNED`：计划完成，可执行
- `RUNNING`：正在传输
- `PAUSED`：已暂停
- `FAILED`：执行失败，可排查后恢复
- `COMPLETED`：执行完成
- `CANCELED`：任务已取消

## 5. 启动执行

接口：

```text
POST /api/transfer/{taskId}/execute
```

说明：

- 适用于 `PLANNED`、`PAUSED`、`FAILED` 状态
- 如果任务正在运行，会因并发锁保护而拒绝重复执行

## 6. 暂停、恢复、取消

暂停：

```text
POST /api/transfer/{taskId}/pause
```

恢复：

```text
POST /api/transfer/{taskId}/resume
```

取消：

```text
POST /api/transfer/{taskId}/cancel
```

注意事项：

- `PLANNING` 阶段不允许暂停或取消
- 暂停/取消为“协作式控制”，会在执行安全点生效
- 恢复操作实际会重新走一次执行入口

## 7. 查询运行指标

接口：

```text
GET /api/transfer/{taskId}/metrics
```

可看到的信息包括：

- 总文件数、总批次数、已传输字节
- 批次状态分布
- 文件状态分布
- 调度策略
- 在途批次数、文件数、字节数
- 背压触发次数与原因
- 执行线程池和协调线程池快照

## 8. 分页查询批次

接口：

```text
GET /api/transfer/{taskId}/batches?page=0&size=100
```

说明：

- `page` 必须大于等于 `0`
- `size` 必须大于 `0`
- `size` 不能超过服务端配置的 `transfer.query-max-page-size`

## 9. 请求链路追踪

建议调用方在每次请求中带上：

```text
X-Request-Id: your-trace-id
```

服务会：

- 原样回显该请求头
- 在错误响应里附带 `requestId`
- 在应用日志中写出同一 `requestId`

这对排查线上问题非常关键。

## 10. 常见错误

### 10.1 源目录不存在

现象：

- 返回 `400`
- 错误信息提示源目录不存在或不是目录

### 10.2 源目录和目标目录互相嵌套

现象：

- 返回 `400`
- 错误信息提示不允许嵌套目录

### 10.3 任务未规划完成就执行

现象：

- 返回 `400`
- 错误信息提示任务还未准备好执行

### 10.4 规划阶段尝试暂停或取消

现象：

- 返回 `400`
- 错误信息提示规划未完成，当前不支持操作

## 11. 典型调用流程

1. 调用 `POST /api/transfer` 创建计划
2. 轮询 `GET /api/transfer/{id}` 直到 `PLANNED`
3. 调用 `POST /api/transfer/{id}/execute`
4. 周期性调用 `GET /api/transfer/{id}` 或 `GET /metrics` 查看进度
5. 需要时调用 `pause / resume / cancel`
